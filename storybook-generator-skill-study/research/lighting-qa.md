# 光影 QA 研究层

## 为什么单独拆出来

角色一致性和图文契约解决的是“画面里有什么”，但没有自动回答“这些东西之间是否存在合理的光学因果”。例如文字说“小拖鞋挡住了兔子灯的光”，画面必须同时满足：灯是光源、鞋子位于光路、墙面是接收面，并且墙上的影子方向与这条关系相容。

## 当前实现

研究站为每一页增加一个轻量 `lighting` 契约：

```text
光源 → 遮挡物 → 投影面
       ↓
预期方向 / 软硬程度 / 跨页变化
```

默认 ImageGen Run 001 的 9 个页面都有这组数据，并通过“光影 QA”页签展示。页面状态分为：

- `pass`：光源和投影因果在当前绘本语境中可读；
- `review`：画面或文字没有充分证明光路，需要局部复查；
- `contract-only`：代码回退或尚无真实图像证据，只展示应当检查的契约。

当前不是完整的光线追踪器，而是语义 + 粗几何的人工可审计层。v1 的第 7 页被标记为鞋子不在明确光路中，第 8 页被标记为树叶和手形影子来源不明；局部重生成后，v2 已分别通过“鞋子投影”和“枝叶投影”检查，旧版仍保留用于对照。

## 可扩展的自动化路线

1. 生成前：为光源、遮挡物、投影面、方向和光色建立结构化契约；
2. 生成后：用检测 / 分割 / VLM 找到灯、道具、墙面和影子；
3. 关系检查：判断遮挡物是否处于光源与投影面之间，影子是否大致朝相反方向；
4. 跨页检查：比较光源位置、色温和影子变化是否符合故事动作；
5. 评分归因：将问题归到缺少光源、光路不成立、影子来源歧义或跨页漂移；
6. 局部返工：只重生成失败页，不让整本书回退。

## 物理边界

绘本插画是二维、风格化和可能多光源的图像，很多遮挡关系在单张图中没有唯一答案。因此验收目标应是“读者能理解的因果关系”，而不是像素级物理正确。只有在关键页面仍然无法判定时，才考虑深度估计、结构控制或 3D 代理场景。

## 研究价值

这层把“一致性”从角色外观扩展到空间和因果：

```text
角色一致性 → 道具一致性 → 光影因果 → 跨页状态连续
```

它是将绘本生成工作流从提示词 SOP 推向可测量、可归因、可局部修复系统的一个自然切入口。

## 本次范围结论

本次提交止步于可审计的语义光影 QA 与局部重生成，不继续实现分割、深度估计或完整光路推理。后续只有在实际项目再次出现高价值的光源 / 投影问题时，才重新开启这条研究线。
