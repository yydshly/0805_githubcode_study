# 研究展示站浏览器验收

## 运行环境

- 时间：2026-08-05（Asia/Shanghai）
- 浏览器：Codex 内置浏览器
- 启动方式：在父仓库根目录运行 `python -m http.server 4173`
- 规范地址：`http://127.0.0.1:4173/awesome-gpt-image-2-study/site/`
- 数据快照：上游提交 `76fcd0e6`；页面目录含 22 个模板、517 个案例、13 个类别、19 个风格和 10 个场景。

## 第 2 版基线与完成结果

实施前桌面基线确认：页面有能力地图与单一茶饮场景，但不存在 `#library`、`#experiment`，也没有场景切换控件。实施后同一地址加载 `catalog-data.js`、`app.js`、`styles.css` 和 3 张本地实验图片；DOM 渲染 22 个模板按钮、12 个首屏案例卡、4 个场景入口和 3 个对照卡。浏览器控制台无 warning 或 error。

## 桌面 1440 × 1000

- 页面可用宽度 1425px，`scrollWidth = clientWidth = 1425`，没有页面级横向溢出。
- 模板浏览器使用左右主从布局；默认选择“商品商业视觉”，完整显示适用条件、建议、陷阱和关联案例。
- 案例搜索“包装”后由 517 条缩小到 9 条；打开第一条后，检视器显示 745 字符 Prompt 和 2 个追溯链接。
- 四场景依次切换为商品、信息图、UI、海报，类别、模板、预览和 Prompt 均变化；结构化视图可被 `JSON.parse` 正确解析。
- 真实生成对照以三列显示短 Prompt、六段模板、Skill Prompt 三张 3:4 样本，并附人工评分、观察和输入说明。

## 平板 768 × 1024

- 页面可用宽度 753px，`scrollWidth = clientWidth = 753`。
- 模板主从布局改为上下结构，模板列表变为两列；案例卡为两列。
- 场景入口为 2×2，三档生成对照改为单列横向内容卡。
- 顶部导航收起，品牌和上游入口保留；所有核心内容仍处在连续阅读顺序中。

## 手机 390 × 844

- 页面可用宽度 375px，`scrollWidth = clientWidth = 375`。
- 模板、筛选器、案例卡、案例检视器和生成对照均为单列；场景入口保持 2×2。
- UI 场景实测：表单 347px、预览 309px、Prompt 255px，均未越过内容边界。
- 生成对照实测：卡片 347px、图片 309px，三张图片均完成加载（原始尺寸 1086×1448）。

## 目录与反馈状态

- 搜索不存在的组合后，计数为 0，空状态可见，“加载更多”隐藏；点击“清空条件”恢复 517 条。
- 点击“再看 12 条”后渲染 24 张卡，范围提示为“显示 1–24 / 517”。
- 点击“复制这个案例 Prompt”后，按钮变为“已复制”，aria-live 提示“内容已复制到剪贴板”。
- 所有案例图片仍留在原始来源；页面只提供元数据、Prompt、原始来源和仓库定位。

## 键盘、语义与降级

- 在 UI 场景 Tab 上按右方向键后，选中和焦点移动到海报场景；活动元素显示约 3px 实线焦点。
- 模板列表支持上下方向键；从 `product-commerce-visual` 移动到 `personalized-beauty-report` 后，`aria-selected` 与实际焦点一致。
- 样式表包含 `prefers-reduced-motion: reduce` 规则，关闭平滑滚动并把过渡/动画降到 0.01ms；四个核心区不依赖动画显示。
- 当前浏览器不能模拟系统 reduced-motion，也不能禁用 JavaScript；已检查媒体规则、静态核心内容和 noscript 说明。这两项保留为环境限制，不影响当前交付。

## 构建

- `node --check awesome-gpt-image-2-study/site/app.js` 通过。
- `node awesome-gpt-image-2-study/scripts/build-site-catalog.mjs` 生成 22 个模板和 517 个案例。
- `node scripts/build-pages.mjs` 成功产出 3 个项目；目标站点构建包含 HTML、CSS、JavaScript、目录数据和 3 张实验图片。

## 第 3 版：真实图鉴与 Skill 沉淀工作台

### 首屏与入口

- 桌面 1440×1000 首屏明确显示两个主入口：“入口一 · 看真实案例”指向 `#library`，“入口二 · 沉淀 Skill”指向 `#demo`。
- 首屏文字把图片定位为案例参考，把 Skill 定位为可重复使用的工作协议，不再把搜索或实时生图描述为核心价值。

### 真实案例图

- 517 条案例数据都包含本地研究地址和固定提交的远程回退地址；当前只对可见案例懒加载图片。
- 桌面案例区当前渲染 12 张图片，滚动进入区域后全部加载成功；前三张原图尺寸分别为 1344×1776、1344×1776、906×1199。
- 选择 Case 520 后，详情同屏显示真实大图、928 字符完整 Prompt、研究用途提示、原始来源和仓库定位。
- 受控失败验证：临时让 Case 520 的本地和远程地址都返回失败，页面进入 `is-error` 状态、隐藏破损图片并显示“图片暂未加载 / Prompt 与来源仍可正常阅读”；标题、Prompt 摘要与按钮保持可用。测试后正式地址和上游文件已恢复。

### Skill 配方

- 商品默认场景显示三组清单，每组 4 条：先补问、生成前检查、生成后验收；配方文本长度 686 字符。
- 切换到 UI 场景后，配方名称、补问问题和 `template: UI 截图系统` 同步更新。
- “复制配方”成功显示剪贴板反馈；“保存到本机”生成一张配方卡并可恢复，“删除”后回到空书架状态。验证用配方已清理。
- 本机沉淀使用 `localStorage`，最多保留 12 条；不上传服务器，不连接图像 API。

### 跨视口

- 1440×1000：案例三列、案例详情图文双栏、Skill 清单与配方双栏；`scrollWidth = clientWidth = 1425`。
- 768×1024：案例两列、详情和 Skill 改为单列；12 张当前图片加载；`scrollWidth = clientWidth = 753`。
- 390×844：案例与 Skill 单列，案例卡 347px、图片 345px、配方面板 347px；`scrollWidth = clientWidth = 375`。
- 最终控制台无 warning 或 error。
