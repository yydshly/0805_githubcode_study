            04 / STATE & MEMORY

            状态不是记忆，
            持久化也不等于长期记忆。

            pi 同时存在 AgentState、LLM Context、JSONL 会话树、压缩摘要、项目知识、配置状态和新的 durable session contract。点击逐项比较。

            8状态与记忆类型

              READ / WRITE / PERSIST

              十种状态，分别由谁读、谁写、保存多久

              用这张矩阵判断某个信息究竟是运行态、工作上下文、会话历史、配置，还是尚未实现的长期记忆。

              状态所有者 / 范围读取者写入者持久化

              CURRENT JSONL DATA MODEL

              九种 SessionEntry，决定什么进入模型上下文

              每一行 JSONL 都是 append-only 树节点；`custom` 与 `custom_message` 的差别尤其重要。

              TWO SESSION ARCHITECTURES

              当前主链和下一代架构必须分开看

              类型、存储后端存在，不代表执行层已经接通。

              CURRENT PRODUCT PATH

              AgentSession + JSONL

              当前 coding-agent CLI 的真实主链。SessionManager 追加消息、模型变化、thinking level、compaction 和分支信息。

              coding-agent/src/core/session-manager.ts
              EVOLVING V2 PATH

              AgentHarness + SessionRepo

              Entry/Record/Lane/SQLite contract 已建立，但 AgentHarness 的 prompt、resume、compact 等仍是 HarnessNotImplemented。

              agent/src/harness/agent-harness.ts
              长期语义记忆缺口

              pi core 没有自动事实提取、embedding、跨会话召回、重要性、更新或遗忘策略。以后开发自己的 Agent 时，这是一层需要单独设计的系统，而不是把 session history 换一个名称。

                    THE CORE LOOP

                    为什么一次请求可能调用模型多次？

                    模型响应toolCall执行工具toolResult再次调用模型直到无工具结束
