# 研究计划

## 研究目标

将 `awesome-gpt-image-2` 从“看起来很丰富的提示词库”拆解为可验证的系统，并判断它对我们自己的视觉生成流程是否有迁移价值。

## 核心问题

### 1. 数据层

- 517 个案例的分类和标签是人工标注、规则生成还是混合流程？
- 类别、风格、场景、模板之间是否存在重复、缺口或含义漂移？
- `cases.json`、`style-library.json`、Markdown 文档和生成后的 Skill 参考文件，哪个是事实源？

### 2. 选择与组装层

- Agent 如何从一句需求选中模板？
- 当前流程是关键词匹配、模型语义推理，还是存在隐藏检索逻辑？
- “类别 → 风格 → 场景 → 相似案例”的顺序在模糊需求下是否稳定？
- 模板约束能否减少文字乱码、布局拥挤、平台特征混杂等常见失败？

### 3. 产品与服务层

- 静态画廊和在线生成服务的边界在哪里？
- 生图接口是否支持编辑、参考图、多尺寸和高质量输出，还是只有文本生图测试？
- 登录、积分、会员、支付和管理后台对核心研究价值有什么影响？

### 4. 可迁移性

- 哪些字段可以成为跨模型 Prompt IR（中间表示）？
- 哪些字段只适用于 GPT-Image-2？
- 如何把模板选择、提示词编译和模型调用解耦？

## 研究阶段

### 阶段 A：静态架构盘点

- 建立目录、数据流和依赖地图。
- 确认事实源与生成产物。
- 统计案例、分类、标签、模板和引用关系。
- 标记文档与代码不一致之处。

### 阶段 B：数据质量审计

- 检查空字段、重复 ID、失效案例引用和缺失图片。
- 分析类别与标签分布是否失衡。
- 抽样检查案例描述、Prompt 和标签是否相符。

### 阶段 C：Skill 行为测试

- 建立覆盖 13 类场景的固定测试集。
- 比较不同表述是否选到相同模板。
- 检查输出是否完整包含六个提示词块。
- 记录错误选择、过度约束和信息遗漏。

### 阶段 D：生成对照实验

- 对同一任务比较“原始短 Prompt / 模板 Prompt / Skill Prompt”。
- 固定模型、尺寸、质量和生成次数。
- 从构图、文字、风格一致性、业务约束满足度进行盲评。
- 将模型随机性与模板收益分开记录。

### 阶段 E：迁移原型

- 设计最小 Prompt IR。
- 实现可替换的模板选择器和模型适配器。
- 形成我们自己的使用指南与实验报告。

## 证据标准

每条结论标记为以下一种：

- **上游事实**：能定位到具体源码、数据、文档或提交。
- **代码推断**：根据实现得出的合理判断，尚未运行验证。
- **实验观察**：在记录环境与输入后得到的结果。
- **待验证假设**：当前证据不足，不能当成结论。

涉及生成质量的判断至少重复三次；涉及模板整体效果的判断必须覆盖多个类别，不能凭单张优秀案例下结论。

## 第一批交付物

- 架构与数据流基线。
- 数据质量审计脚本和报告。
- Skill 固定测试集。
- 三组以上 Prompt 对照实验。
- 跨模型 Prompt IR 草案。
