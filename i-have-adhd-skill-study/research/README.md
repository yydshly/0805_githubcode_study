## 核心结论

`i-have-adhd` 不是 Prompt 改写器，也没有独立的业务分析逻辑。宿主大模型仍负责理解用户问题、读取代码、判断原因和形成答案。这个 Skill 追加一套元策略，控制最终回答的信息选择、优先级、步骤颗粒度、状态提醒和语言压缩。

对于当前能力较强的大模型和成熟 Agent 产品，这些能力通常已经存在于模型能力或宿主系统规则中，因此安装完整 Skill 的增量意义有限。它不会增加新的分析能力，主要作用是固定输出偏好。当前研究决定为：**暂时归档，保留为 Skill 写法和产品包装案例**。

它的逻辑可以整理为五个真实阶段：

1. **入口与激活**：Skill 名称、用途描述或用户调用让宿主加载正文。
2. **基础分析**：宿主模型按原能力分析任务，Skill 不提供新的领域知识。
3. **例外路由**：解释请求、危险操作、连续失败、真实歧义和上层规则冲突进入不同分支。
4. **输出塑形**：行动置顶、多步编号、抑制支线、重述状态、具体时间、显示成果、错误按“位置—原因—修复”表达。
5. **发送前检查**：模型自行删除前言、题外话、无效缓和语和客套结尾，并留下一个具体下一步。

## 事实与推断边界

- 上述十条规则、六类例外和发送前检查来自上游 `SKILL.md`。
- “输出分布受到上下文条件影响”是对大模型指令遵循机制的研究解释，不是上游仓库实现的算法。
- 上游没有程序化校验器，因此列表长度、时间估计和发送前检查都属于软约束。
- 上游没有 Token 基准测试。“可能省 Token”主要来自输出缩短和减少重复沟通；加载 Skill 正文本身会增加输入 Token。
- ADHD 相关陈述是产品设计假设，不应视为医学诊断、临床验证或治疗建议。

## 可参考价值

最值得复用的是“抽象目标 → 可观察规则 → 正反例 → 例外路由 → 发送前检查”的 Skill 写法，而不是底层技术。它适合成为行动型输出模式的基线；若需要强一致性，还应增加结构化输出、自动校验和真实用户测试。

对于现代 Agent，优先使用宿主已有规则，或者只在 `AGENTS.md` 中保留 3—5 条真正缺失的偏好。除非存在可复现的输出问题，不建议默认加载整份 Skill。
