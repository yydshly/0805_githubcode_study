## 浏览器缺陷与修复

第一次运行六段工作流时，第 3 段日历中的 Markdown 反引号落在 JavaScript 模板字符串中，被解释成模板标签调用。计时器随后继续解锁后续步骤，使界面呈现“完成”但控制台已有错误。

修复内容：

1. 把模板中的反引号改为 HTML `code` 元素。
2. 在每段装配处加入错误保护；任一段渲染失败会停止运行并显示 `ERROR`，不会继续伪装成完成。
3. 使用新浏览器标签完整重跑，6/6 步骤、100% 进度和最终产物一致，控制台无错误。

## 键盘、状态与复制反馈

- 能力地图与六段流程都使用 `tablist/tab/tabpanel` 语义。
- 能力地图通过左右方向键从“母题与栏目”切换到“发布规划”，焦点和详情同步。
- 实际流程通过左方向键从“标题”切换到“日历”，焦点、选中态和输出同步。
- 焦点轮廓为可见实线。
- 复制按钮在完成后启用，并显示“已复制”和对应 aria-live 反馈。浏览器验收接口没有提供可靠的系统剪贴板内容回读，因此本次只验证了页面交互与成功反馈，不把剪贴板内容回读记为已验证。

## 延期项

`prefers-reduced-motion` 规则存在，且匹配时工作流会同步装配、不使用分段等待。当前浏览器只暴露 `viewport` 与 `visibility` 能力，无法模拟系统媒体偏好；已检查默认偏好为 false 和 CSS 规则存在。待浏览器支持媒体偏好模拟时复测真实匹配态。
