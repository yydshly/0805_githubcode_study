# 研究展示站设计契约

Entry mode: Brief-led implementation
Request revision: 3
Target user and context: 想评估或落地 AI 视觉生成的产品、设计、运营和开发人员；他们可能不了解 Prompt-as-Code，需要在十分钟内形成正确心智模型并带走可用 Prompt。
Desired first impression: 这是一个可信、清晰、能动手操作的研究工作台，不是图片瀑布流或营销落地页。
Visual ambition: Editorial
Experience architecture: Editorial Flow
Visual constraints: 明亮纸张底色、深墨文本、青绿色作为结构色、珊瑚红作为行动色；用代码化视觉和少量渐变表达“Prompt 编译”，不依赖外部图片或重型视觉库。
Information constraints: 首屏先说明“它是什么/不是什么”；能力地图必须覆盖数据、模板、Skill、产品四层；案例演示必须显示业务输入、路由依据、六段 Prompt 和约束；扩展部分必须给出选择模板和落地步骤。
Operation constraints: 纯静态前端，无登录、无后端、无真实图像 API；所有演示数据内置；复制功能有降级反馈；主要旅程可用鼠标和键盘完成。
State constraints: 能力类别筛选、演示输入变化、Prompt 视图切换、复制成功/失败、应用向导选择和导航状态必须可理解；JavaScript 不可用时仍能阅读核心内容。
Environment constraints: 部署到现有 GitHub Pages 多项目结构；直接使用 HTML/CSS/JavaScript；支持当前主流浏览器；目标宽度为桌面 1440、平板 768、手机 390。
Primary journey: 进入页面 → 建立能力心智模型 → 操作“新品茶饮上市”演示 → 看见需求如何被路由并编译为 Prompt → 复制结果 → 使用应用向导迁移到自己的任务。
User-defined phases: 第一，网页展示库的能力；第二，结合实际场景演示；第三，扩展解释并帮助用户应用。
Required artifacts: 可运行站点、设计契约、覆盖清单、浏览器验收记录、交接说明、父项目发布配置。
Autonomy authorization: 用户明确要求执行三个阶段；允许在现有研究子项目内直接实现可逆的静态网页与研究文档。
User-decision boundary: 引入真实付费 API、第三方账号登录、复制或公开第三方图片、修改上游仓库、正式发布到远程环境需另行授权。
Observable completion criteria: 三个用户阶段在同一页面有清晰入口；演示输入能实时改变路由摘要、预览和 Prompt；Prompt 可切换结构化/普通版本并可复制；应用向导能根据选择输出建议；1440/768/390 宽度无横向溢出或遮挡；键盘焦点可见；reduced-motion 不隐藏信息；构建脚本包含该项目并成功产出页面。

## 第 2 版请求增量（2026-08-05）

用户确认按推荐补齐当前网页尚未展示的能力，页面从“单一示例讲解页”升级为“可检索、可试验、可对照的研究工作台”。本轮保留既有视觉语言和三阶段叙事，不重做品牌方向。

- 新的主旅程：建立心智模型 → 浏览 22 个模板与 517 个案例 → 在信息图、UI、海报、商品四类场景中试验 → 对照短 Prompt、模板 Prompt、Skill Prompt 的一次真实生成样本 → 带走适用方法与风险边界。
- 新的必需产物：可复现的站点目录数据、模板与案例筛选器、案例 Prompt 检视器、四场景实验室、三档 Prompt 对照实验及其方法说明。
- 数据约束：模板与案例必须由固定上游快照生成，不手写伪造数量；案例图片不搬运到项目内，使用元数据、Prompt 和原始来源链接；筛选结果必须显示当前数量、空状态和复位入口。
- 对照实验约束：明确标注为单次样本和人工观察，不宣称科学因果；三档输入的任务目标一致，展示文字准确性、布局控制、风格匹配与约束遵循四个维度。
- 状态约束：目录搜索、分类/风格/场景筛选、模板选择、案例分页或加载更多、场景切换、Prompt 视图切换和复制均需有可理解反馈；键盘可完成核心旅程。
- 响应式约束：1440px 时目录采用主从布局；768px 压缩为上下文连续的单列或双列；390px 时筛选、场景切换、对照卡片不得产生页面级横向溢出。
- Observable completion criteria v2：22 个模板和 517 个案例均可由页面数据访问；四类场景均能产生对应结构化 Prompt 与预览；三档对照样本、输入差异和观察结论同屏可追溯；新增交互在 1440×1000、768×1024、390×844 通过主流程、键盘、控制台和 reduced-motion 检查。

## 第 3 版请求增量（2026-08-05）

用户明确不需要把案例检索或实时生图作为主价值；图片用于理解案例，真正需要强化的是“图鉴入口”和“可沉淀的 Skill 工作方法”。本轮把页面的主入口收敛为两个清晰方向。

- 入口一“案例与模板图鉴”：22 个模板与 517 个案例继续完整可访问；案例卡必须展示上游真实案例图、标题、Prompt 摘要、标签和来源入口，详情必须同时显示大图与完整 Prompt。
- 入口二“Skill 沉淀工作台”：多场景实验室从四个固定样例升级为可复用配方原型，明确显示场景输入、模板规则、必须追问、生成前检查、生成后验收和可保存的 Skill 配方文本。
- 图片边界：案例图只通过固定上游提交的公开资源地址加载，显示来源与研究用途提示，不复制到本项目资产中；图片加载失败时必须保留可读的标题、Prompt 和来源链接。
- 信息层级：首屏和导航优先让用户选择“看真实案例”或“沉淀 Skill”；搜索仍作为图鉴内的辅助能力，不再被描述为产品核心。
- 状态约束：案例图片加载、失败占位、详情选择、Skill 配方切换、规则勾选、复制和重置必须有清晰状态；不接入真实生图 API。
- Observable completion criteria v3：首屏存在两个明确入口；首屏案例卡可见真实上游缩略图，案例详情同时显示大图和完整 Prompt；四场景均输出可复制 Skill 配方、追问清单与检查清单；图片失败不影响案例阅读；1440/768/390 无页面级横向溢出，键盘与控制台检查通过。

## 设计方向

| 决策 | 选择 | 服务目标的原因 | 可观察约束 | 验收标准 |
| --- | --- | --- | --- | --- |
| 信息层级 | “认识 → 演示 → 应用”三幕式阅读流 | 对应用户原始三阶段 | 首屏只保留一个主行动入口 | 首次扫描能识别三个阶段和下一步 |
| 主视觉 | Prompt 编译流水线而非图库拼贴 | 强调库的真正价值是结构化协议 | 不使用无法追溯的第三方图片 | 无图片时仍能解释系统工作方式 |
| 字体角色 | 中文无衬线正文 + 等宽数据/Prompt | 区分研究解释与机器协议 | 正文行宽不超过约 72 字符 | 长 Prompt 仍可读、可滚动、可复制 |
| 色彩语义 | 青绿=结构与通过，珊瑚=行动与风险，墨色=事实 | 强化教学路径 | 不只依赖颜色表达状态 | 标签同时有文字或图形提示 |
| 材质与深度 | 纸张背景、细边框、少量硬阴影 | 保持研究台感，减少 SaaS 模板感 | 卡片层级最多三层 | 桌面和手机均无过度装饰 |
| 响应式 | 桌面双栏，平板压缩，手机单栏 | 保持同一学习闭环 | 操作区在窄屏不脱离上下文 | 390px 能完整完成演示与复制 |
| 状态反馈 | 文本状态、按钮状态、aria-live | 让复制和推荐结果明确 | 无无声失败 | 成功和降级路径都给出可恢复反馈 |
| 动效 | 仅用于筛选、Prompt 更新和进度提示 | 解释状态变化 | reduced-motion 时取消位移和过渡 | 关闭动效后信息和操作不受影响 |
