# 阶段归档 · The Long Silence / First Canto

> 状态：阶段性完成，暂时归档  
> 日期：2026-08-06  
> 对应版本：研究修订 v12  
> 当前入口：`http://127.0.0.1:5180/`

## 一句话结论

原库最值得参考的不是它作为“完整游戏”的表现，而是它把**可信飞船资产、程序化宇宙、内外空间呼应、确定性状态和宇宙考古叙事**组合成了可继续扩展的探索框架；本 Demo 已把这些价值整理成一段可玩的 `First Canto · 1/7` 垂直切片。

## 这次研究回答了什么

最初的问题是：这个仓库有什么能力、原理是什么、什么场景下使用、对我们的意义是什么。实际运行后发现，原作当前游戏完成度和直接游玩价值有限，因此研究重心从“复刻游戏”转为：

1. 找出可以迁移的方法，而不是照搬完整玩法。
2. 用一个小型 Demo 验证这些方法能否共同工作。
3. 让页面同时解释生成方式、操作方式、已接入范围和后续边界。
4. 用故事为驾驶与扫描提供原因、发现和奖励，避免只剩技术展示。

## 从开源库到我们的项目

这次工作的关系不是“找到一个项目，然后把它改成我们的游戏”，而是：

**开源库提供可运行证据 → 我们拆解其中的有效方法 → 用小 Demo 验证迁移价值 → 只把通过验证的部分沉淀为自己的能力。**

| 阶段 | 开源库提供什么 | 我们做了什么 | 最终留下什么 |
|---|---|---|---|
| 观察 | 飞船外形、真实内舱、程序化系统、相对原点和 Silence 世界观 | 实际运行并检查效果、代码、资产和玩法完成度 | 对原库能力与缺陷的真实判断 |
| 提炼 | 已经存在的技术与美术样本 | 区分“值得迁移的方法”和“当前不值得复制的游戏内容” | 飞船语言、内外呼应、确定性生成、可观测反馈等原则 |
| 重组 | 可复用代码、资产和叙事母题 | 用新的信息架构、驾驶门槛、共鸣器任务和页面说明重新组合 | First Canto 可玩垂直切片 |
| 验证 | 一个可比较的上游基线 | 做桌面试玩、移动布局、高保真切换、降级和视觉回归 | 有证据的取舍，而不是主观“感觉不错” |
| 沉淀 | 开源许可允许的起点 | 记录来源、边界、设计合同、测试证据和恢复方式 | 可以继续复用的项目能力与研究流程 |

因此，开源库对我们项目的意义主要有四点：

1. **它是加速器，不是产品答案。** 它让我们跳过部分从零试错，快速获得可信飞船、内舱资产和空间技术样本，但不会替我们完成玩法、叙事节奏与产品定位。
2. **它是参照物，不是必须遵循的模板。** 原作运行效果较弱，反而帮助我们看清：优质资产和技术能力如果没有行动原因、结果反馈与内容变化，也不会自动变成好游戏。
3. **它是可验证的零件库。** `buildHull`、Draco 内舱、确定性生成、相对原点等能力可以被单独验证、替换和组合，而不必把整个仓库绑定进未来架构。
4. **它帮助我们建立边界。** 我们明确没有必要复制完整引擎、六自由度、着陆和七星系内容；这避免项目因为“开源代码已经有了”而无目的膨胀。

我们的项目由此获得的不是一个换皮版本，而是一个经过筛选的起点：保留上游已经证明有效的结构，把玩法驱动、叙事状态、移动适配、性能降级和研究说明变成自己的实现与判断。

## 这次研究对你的意义

这次研究最重要的产物也不是当前这个 Demo，而是一套以后可以重复使用的判断方法。

1. **你获得了评估开源项目的方法。** 不再只看 README、截图或“能否运行”，而是分别判断资产质量、技术机制、玩法完成度、迁移成本和许可证边界。
2. **你把模糊感受转成了明确决策。** “飞船效果不错”“游戏不好玩”“星球像在同一平面”最终都被转成可执行问题，并通过高保真对照、任务链和视觉轨道得到验证。
3. **你知道什么值得拿，什么应该放弃。** 这比把整个仓库接进来更有价值：保留飞船与世界构建方法，放弃低价值的完整复刻和无目标扩张。
4. **你形成了一份自己的知识资产。** 设计合同、覆盖表、浏览器证据和阶段归档，使这次思考不会随着对话结束而消失；以后研究其他开源库可以复用同一流程。
5. **你降低了未来决策成本。** 下一次不需要重新争论“是否做六自由度、是否铺七个星系”，除非新的用户价值或证据足以推翻当前边界。
6. **你拥有了一个研究仪器。** 当前 Demo 的价值是快速验证下一条假设，例如“第二台共鸣器是否需要不同玩法”，而不是急着把它包装成最终产品。

更直接地说：这次研究让你从“看到一个有意思的开源项目”前进到了“能够判断它对自己有什么用，并把有用部分转化成自己的项目能力”。这才是开源研究真正产生复利的地方。

### 同样重要：它不代表什么

- 不代表拥有一个可以直接商业化的完整游戏。
- 不代表上游所有代码和故事都适合继续继承。
- 不代表已经找到长期内容循环；目前只证明第一段垂直切片成立。
- 不代表以后必须沿着这个题材继续；即使更换世界观，本次沉淀的评估与实现方法仍然有效。

## 玩家现在为什么要玩

当前主路径已经形成完整的“问题 → 证据 → 新目标 → 回答”结构：

1. **任务简报**：四万年前，九百个世界在四天内沉默，没有战争或灾难痕迹。
2. **接近 ITHIRKA II**：玩家必须真实驾驶、控制距离和速度。
3. **第一次扫描**：发现城市和轨道仍然完整，唯一异常是一束持续四万年的共鸣信号。
4. **追踪 RESONATOR I**：目标遥测切换为频率、年代与 `WAITING` 状态。
5. **完成调谐**：取回 `THE FIRST CANTO · 1/7`，得知 Choir 最先建造的是聆听塔，而宇宙像是在屏息。
6. **留下下一问**：沉默不是普通毁灭；其余六台共鸣器仍然等待。

故事不是独立背景文章。任务简报、HUD、目标名称、遥测、按钮、场景说明和完成奖励共用同一任务状态。

## 已经沉淀的可迁移价值

### 1. 飞船需要“结构语言”，不只是科幻外形

- 远处先读出长轴、锤头、散热翼、背鳍和分离引擎。
- 压力壳、承力结构、金属连接和发光件使用不同材料语义。
- 外部发光座舱与内部控制台、框架和窗外目标互相证明尺度。
- 轻量几何适合解释设计原则，高保真资产负责验证近景可信度。

### 2. 生成必须可重复，才能被设计和测试

- 固定 seed 生成恒星、行星、颜色、轨道和共鸣器路线。
- 同一 seed 的故事航点也保持稳定，不把叙事线索交给不可复现的随机数。
- 飞船和任务目标使用稳定 XZ 玩法平面；背景轨道按 seed 倾斜，建立三维纵深但不增加操作负担。

### 3. 技术状态必须成为玩家可见的反馈

- 位置、船头、速度和目标共同决定扫描是否可用。
- 扫描同时驱动空间光束、目标环、HUD、遥测、进度和文字。
- FPS、draw calls、三角形、像素比、资产状态与 LOD 都直接来自运行时。
- WebGL 不可用时保留故事和研究结论，并安全关闭无效操作。

### 4. 一次结果应该自然生成下一步

第一次扫描不只显示“完成”，而是给出异常证据并定位共鸣器；第二次扫描也不只完成 2/2，而是解锁 Canto。这个结构比增加更多随机目标更值得复用。

## 来源、提炼与未接入内容

### 直接复用或按需接入

- 上游 `buildHull` 程序化高保真船体。
- 11 个 Draco 内舱文件及 AO、albedo、normal、ORM 材质。
- MIT 许可范围内的结构与资产；声明见根目录 `THIRD_PARTY_NOTICES.md`。

### 本 Demo 的重新组织与实现

- 轻量程序化飞船、双层外部/驾驶舱场景和共享任务状态。
- 单平面驾驶、扫描门槛、碰撞安全边界和追随镜头。
- 确定性双目标航程与倾斜背景轨道。
- 自适应画质、源库船体几何 LOD、加载反馈和文本降级。
- 将原作世界观概括为第一段 Canto 任务闭环；没有复制大段原文。

### 明确没有接入

- 完整七个星系、七段 Canto 和最终 Aperture。
- 六自由度飞行、着陆、行星表面探索、战斗和存档。
- 完整行星烘焙、成片级后处理与生产级音频。
- 原库的完整引擎、全部指令系统或完整故事流程。

## 当前验证证据

- 桌面完整路径：`3.49u → 扫描 ITHIRKA II → TRACE FOUND → 左转 88° → RESONATOR I → 2.61u READY → CANTO 1/7`。
- 完成态切换源库高保真后保持 `L2/L3 · SOURCE` 与 `RESONATORS 1/7`。
- `?webgl=off` 中故事可读，23 个 3D 专用控制安全禁用。
- desktop/mobile × study/fallback 四场景视觉回归均为 `PASS 0.000%`。
- `npm run build` 通过；主入口约 680.10 KiB，gzip 179.24 KiB，高保真模块继续按需分包。
- 详细过程见 [浏览器证据](../browser-evidence.md) 与 [覆盖清单](../coverage-manifest.md)。

## 当前不足与技术债

1. 只有第一段 Canto；还无法证明七段内容能持续提供不同体验。
2. 两次核心操作仍然都是接近、制动、扫描；故事改善了意义，但没有改变第二次交互结构。
3. Canto 当前是信息奖励，还没有真正改变飞船能力或后续决策。
4. 没有推进、扫描、调谐和 Canto 解锁的完整音频层。
5. 主入口仍包含 Three.js，超过 500KB；若产品化，应延迟加载 3D 核心或继续拆包。
6. 开发构建依赖相邻目录 `../the-long-silence` 的上游源码；移动或独立分发前需要固化依赖策略。
7. 文本降级已通过确定性夹具验证，但真实 GPU 黑名单和驱动故障仍需硬件矩阵复测。

## 下次恢复研究时先做什么

先提出新的研究问题，不要从无目的视觉优化开始。推荐问题是：

> 第二台共鸣器能否用一种不同于“再次扫描”的交互，并给玩家一个会改变后续航行的能力奖励？

若答案值得验证，建议只做第二段小切片：

1. 为 Resonator II 设计不同的调查动作，例如频谱对齐、遮挡定位或在内外视角间交叉判断。
2. 让 Second Canto 解锁一个真实能力，例如更远扫描、信号方向提示或新的折跃选择。
3. 对比第一段和第二段是否产生不同思考，而不是只增加文案和航点数量。

暂不优先：六自由度、着陆、随机任务树、完整战斗、一次性铺满七个星系。
