# i-have-adhd Skill 研究站

> 状态：**暂时归档**  
> 归档结论：对当前能力较强的大模型和成熟 Agent 产品，这个仓库提供的主要能力通常已经内置，完整安装后的增量价值有限。保留本项目作为 Agent Skill 写法、输出策略和产品包装案例，不继续投入功能研究。

这是 `0805 GitHub Code Study` 的第 06 个研究子项目。研究对象是 [`ayghri/i-have-adhd`](https://github.com/ayghri/i-have-adhd)，研究快照为 `0047e0d323af880d4a32acbcc8bf58b3ca3bb280`。

## 最终结论

`i-have-adhd` 不是 Prompt 改写器、独立分析模型或新的推理算法。宿主大模型仍然负责理解用户问题、读取项目、判断原因和形成答案；该 Skill 只追加一套自然语言输出策略，控制答案的信息选择、优先级、步骤颗粒度、进度提醒和语言压缩。

它的核心机制可以缩写为：

```text
用户原始问题
+ Skill 输出规则
+ 宿主与安全规则
→ 同一个大模型分析并生成答案
```

因此，这个仓库不会增加模型“会不会”的能力，只会提醒模型“这次优先怎样回答”。

## 为什么认为增量意义有限

当前强模型和成熟 Agent 产品通常已经隐含或明确实现了这些能力：

- 直接给答案或下一步行动。
- 把多步骤任务拆成编号清单。
- 根据上下文控制篇幅和解释深度。
- 在连续任务中维护计划和进度。
- 对危险操作先确认，对歧义请求先澄清。
- 以位置、原因和修复方式描述错误。

在 Codex 等成熟 Agent 环境中，系统规则往往已经要求结果优先、持续推进、危险操作确认、工具调用说明和简洁交付，与该 Skill 的十条规则高度重叠。继续加载完整 Skill 可能带来：

1. 重复已有系统规则；
2. 增加输入 Token；
3. 与宿主规定的说明、计划或安全流程发生局部冲突；
4. 让用户误以为安装了新的分析能力；
5. 缺少程序化校验，仍不能保证模型每次严格遵守。

对于当前项目环境，更合理的方式是按需保留少量核心偏好，而不是始终加载整份 Skill：

```markdown
## 输出风格

- 先给答案或下一步，再解释原因。
- 多步骤任务使用编号，每一步只包含一个动作。
- 当前问题完成前不要展开支线。
- 错误说明包含位置、原因和修复。
- 结尾只保留一个明确的下一步。
```

## 它仍然有什么价值

“增量意义有限”不等于完全没有参考价值。这个仓库仍适合作为以下案例保留：

- **Skill 写法案例**：把抽象目标拆成可观察规则、正反例、例外路由和发送前检查。
- **输出偏好预设**：在容易冗长或指令遵循较弱的模型中固定回答风格。
- **跨模型一致性**：为多个 Agent 提供相近的输出约定。
- **产品包装案例**：用清晰命名、简单安装和鲜明定位传播一组常见提示词规则。
- **无障碍设计讨论入口**：提醒产品关注工作记忆、行动摩擦和信息密度，但不能视为医学验证或治疗方案。

它的主要价值是“规则设计与产品表达”，不是底层技术创新。

## 我们确认的工作原理

完整流程被整理为五个阶段：

1. **入口与激活**：宿主根据名称、描述或用户调用加载 `SKILL.md`。
2. **基础分析**：宿主模型按原有能力理解任务；Skill 不提供新的领域知识。
3. **例外路由**：详细解释、危险操作、连续失败、真实歧义和上层规则冲突进入不同分支。
4. **输出塑形**：行动置顶、多步编号、抑制支线、重述状态、具体时间、显示成果。
5. **发送前检查**：模型自行删除前言、题外话、无效缓和语和客套结尾。

其中“例外路由”和“发送前检查”仍然只是模型读取的自然语言指令，不是确定性的状态机或校验程序。

## 关于 Token

该 Skill 可能通过缩短输出、减少题外话和降低重复沟通来节省输出 Token，但它自身也会增加输入 Token。

```text
总 Token
= 用户输入
+ 系统与宿主规则
+ Skill 正文
+ 模型输出
+ 后续重复沟通
```

因此：

- 短问题或宿主已有同类规则时，可能反而增加总 Token。
- 长回答或模型经常跑题时，可能减少输出 Token。
- 长期排错中，如果它真的减少了反复澄清，才更可能产生净节省。
- 上游没有提供 Token 基准测试，“省 Token”不能视为已经验证的性能结论。

## 事实与边界

- 十条规则、六类例外和发送前检查来自上游核心 `SKILL.md`。
- “上下文规则改变模型输出分布”是本研究对大模型指令遵循机制的解释，不是上游实现的新算法。
- 上游没有自动规则检测器、模型微调、RAG、独立状态机或第二模型。
- ADHD 相关表述属于产品设计假设，不应视为医学诊断、临床结论或治疗建议。
- 完整中文版属于研究性翻译，命令、路径和模式关闭短语保留原文。

## 归档决定

本项目暂时归档，保留页面、中文 Skill、研究判断和验证记录，不继续扩展功能，也不默认建议在现代 Agent 中安装完整 Skill。

以下情况可以重新开启研究：

- 上游加入可验证的新机制，而不只是修改提示词文本；
- 出现模型或平台间的真实对照实验；
- 有 Token、任务完成率或无障碍用户测试数据；
- 需要为弱模型或特定产品建立跨模型输出基线；
- 当前 Agent 的默认输出在真实任务中持续出现可复现问题。
