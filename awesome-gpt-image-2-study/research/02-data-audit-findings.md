# 数据审计初步发现

本记录解释 `research/generated/data-audit.json` 的结构检查结果。数字对应固定提交 `76fcd0e6b3961ef2b041547aac654f1efd1ef270`。

## 结论摘要

数据层的**引用完整性总体良好**：案例总数声明与实际一致，没有重复案例 ID、缺失 Prompt 或缺失本地图片；22 套模板引用的案例、文档锚点和封面全部存在；案例数据与风格库的类别、风格、场景目录完全一致。

需要继续研究的问题主要不是“文件坏了”，而是**内容辨识度、来源完整性和产品约束不一致**。

## 1. ID 不连续但不构成引用损坏

案例 ID 范围是 1–520，实际为 517 条，缺少 12、169、170。当前没有模板引用这三个 ID，因此不会造成 Skill 的悬空案例引用。

待确认：这些 ID 是删除、版权下架、导入失败还是有意保留的编号空位。研究报告应使用“517 条、最大 ID 520”，避免把最大 ID 当成案例数量。

## 2. 标题大量泛化复用

审计发现 24 组重复标题，其中包括：

- “信息图可视化设计”27 次
- “主题海报版式设计”21 次
- “界面交互设计图”14 次
- “综合应用场景图”12 次
- “关系图谱信息图”9 次

这不会破坏 ID 检索，但会降低标题搜索、案例辨识和评估数据集的可读性。标题看起来更像批量生成的类别描述，而不是稳定的案例名称。

后续建议：将 `id + title` 作为展示标识；如要制作测试集，应另建人工校正的任务名，不直接把 `title` 当作语义标签。

## 3. 25 条案例缺少来源 URL

缺失集中在案例 1–16 的多数条目、270，以及 330–338。后一个区间在上游 README 中被描述为原创测试，因此缺外部 URL 可能是合理的；早期案例和 270 仍需逐条确认来源字段为何为空。

这影响的是可追溯性和版权判断，不影响本地展示。任何商业复用前，都不能仅凭 `sourceLabel` 或仓库 MIT License 推断案例素材授权。

## 4. Prompt 长度跨度非常大

当前 Prompt 最短 10 字符，最长 8051 字符；中位数约 1023，P95 约 3122。极短 Prompt 可能不是生产级样本，极长 Prompt 则可能与网站限制冲突。

上游在线生图 API 把 Prompt 长度限制为 6000 字符。因此，超过该限制的案例即使能在画廊展示和复制，也无法原样通过网站测试接口。审计脚本已将这些案例单独列出，下一步需确认前端是否提前截断或提示。

当前有两条超过限制：案例 327 为 8051 字符，案例 218 为 6289 字符。这是一个明确的“内容库允许、在线产品拒绝”的契约差异。

## 5. 标签分布明显偏斜

使用最多的场景是 Tech（382）与 Commerce（359），远高于其他场景；风格中 UI（238）、Realistic（198）、Poster（183）占据主导。

这不必然表示标注错误，但意味着：

- 随机抽样会严重偏向科技、商业、UI 与海报。
- Skill 测试集必须分层抽样，而不能按整体比例抽样。
- “该库适用于所有视觉场景”的说法需要谨慎，覆盖数量不等于各类效果均衡。

## 下一步

1. 抽查缺来源 URL 的 25 条案例，区分原创、缺失与不可追溯。
2. 检查超过 6000 字符限制的 Prompt 在网站中的真实交互。
3. 对每个类别选取 3 个案例，人工核对标题、Prompt、风格和场景标签。
4. 设计平衡的 Skill 测试集，避免由高频标签主导结论。
