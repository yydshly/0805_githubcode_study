# 架构基线

## 一句话模型

`awesome-gpt-image-2` 是一个围绕结构化案例数据构建的多出口系统：同一批视觉知识同时供应案例网站、模板文档和 Agent Skill；网站再通过服务端代理接入图像模型与商业账户系统。

## 分层

| 层 | 主要位置 | 职责 | 初步性质 |
| --- | --- | --- | --- |
| 案例数据 | `data/cases.json`、`data/images/` | 保存案例、Prompt、来源、标签和展示图片 | 核心内容资产 |
| 风格知识 | `data/style-library.json` | 定义类别、风格、场景、模板、建议、陷阱和案例引用 | 结构化事实源 |
| 模板文档 | `docs/templates.md` | 提供自然语言与 JSON 填空模板、避坑说明 | 人工可读协议 |
| Skill | `agents/skills/gpt-image-2-style-library/` | 指导 Agent 选择模板并组装生产级 Prompt | 模型驱动的选择层 |
| 生成脚本 | `scripts/generate-site-data.mjs`、`scripts/generate-style-skill.mjs` | 校验源数据并生成网站与 Skill 所需产物 | 构建时同步层 |
| 前端网站 | `src/` | 浏览、筛选、复制、收藏、登录、试生成和账户管理 | 产品界面 |
| 服务端 API | `api/` | 鉴权、生图、额度、收藏、支付、会员和管理统计 | 产品服务层 |
| 数据库 | `supabase/migrations/` | 用户、额度、交易、收藏和付费社区数据 | 持久化层 |

## 两条主要数据流

### 知识构建流

```text
cases.json + style-library.json + templates.md
                ↓ 构建脚本校验/生成
       网站数据 + Skill reference
                ↓
          人工浏览或 Agent 选择
                ↓
             最终 Prompt
```

### 在线生成流

```text
案例 Prompt / 用户修改
        ↓
前端登录态与请求
        ↓
服务端鉴权、额度预留
        ↓
Ciyuan 兼容图像接口
        ↓
gpt-image-2：1 张、1024×1024、low、JPEG
        ↓
成功记账；失败释放额度
```

## 已确认事实

- 当前快照包含 517 个案例、13 个类别、19 个风格、10 个场景和 22 套模板。
- Skill 明确要求按“模板类别 → 视觉风格 → 场景 → 最近案例”的顺序匹配。
- Skill 的最终 Prompt 由六类信息构成：主体任务、构图布局、风格材质、文字标签、比例格式、限制与负面细节。
- `generate-style-skill.mjs` 从 `style-library.json` 生成 Skill 参考文件，并验证模板 ID、类别、风格、场景、锚点与封面。
- 在线生图接口当前只接收文本 Prompt 和案例 ID；没有看到参考图上传或编辑参数。
- 生图接口把请求发送到可配置的 Ciyuan 地址，模型名为 `gpt-image-2`，参数固定为 1 张、1024×1024、低质量 JPEG。
- 网站功能明显超出提示词画廊，还包含 Supabase 登录、收藏、额度、Stripe/支付宝、会员和管理指标。

## 关键判断

### 它不是模型增强层

仓库没有训练代码、权重或微调管线。提示词模板可以提高任务描述的完整性，但不会改变底层模型能力，也不能自动保证文字完全正确或系列图片绝对一致。

### 它暂时不是传统 RAG

在当前静态代码中，没有看到向量数据库、Embedding 或相似度检索服务。Agent Skill 读取静态参考资料后，主要依赖大模型自身完成语义分类、模板选择和字段组装。网站筛选与 Agent 的“最近案例”选择需要分别研究，不能笼统称为同一个检索系统。

### “Prompt as Code”更像中间表示

模板把业务需求拆成稳定字段，使 Prompt 更容易复用、审查和批量生成。但仓库同时存在 JSON 模板、Markdown 模板和最终自然语言 Prompt，目前还没有严格、统一、可执行的 Prompt Schema。把它称为“代码”是一种方法论表达，不代表已经具备类型系统、编译器和跨模型适配层。

## 风险与待验证项

1. **幸存者偏差**：案例库主要展示成功作品，不能直接证明模板普遍有效。
2. **数字漂移**：README、模板文档与数据文件中的案例数或模板数可能不同，需要确认生成流程是否强制同步。
3. **标签质量**：风格和场景数量较少，可能不足以表达镜头、材质、时代、品牌规范等细粒度需求。
4. **案例版权**：代码 MIT 不等于第三方案例图片和 Prompt 可自由商业使用。
5. **供应商耦合**：网站调用第三方兼容接口，实际能力、成本与官方接口可能不同。
6. **评估缺失**：现有自动化测试集中在部分服务端逻辑，尚未看到 Prompt 选择准确率或生成质量回归测试。
7. **固定参数偏差**：网站低质量方形输出适合快速测试，但不能代表模板在其他比例、质量和编辑任务中的表现。

## 下一步建议

优先进行数据质量审计，而不是立即重做界面。先回答数据是否一致、模板引用是否完整、标签是否足够稳定；随后建立固定 Skill 测试集，最后再花费图像额度进行生成对照实验。
