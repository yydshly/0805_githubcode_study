# 研究展示站交接

## 当前结果

研究站已从“能力说明 + 单一示例”升级为完整研究工作台，学习路径现在是：理解四层能力 → 浏览 22 个模板与 517 个案例 → 在四种场景中试验 → 比较三档真实生成结果 → 迁移到自己的任务。

## 已实现

- **完整目录**：22 个模板均有适用条件、建议、陷阱和关联案例；517 个案例可按关键词、类别、风格、场景筛选，并能查看完整 Prompt、原始来源和仓库定位。
- **四场景实验室**：商品、信息图、UI、海报分别有业务字段、代码化预览、模板路由、自然语言 Prompt、JSON Prompt 和复制反馈。
- **真实生成对照**：短 Prompt、六段模板、Skill Prompt 三档各有一张真实样本；页面明确展示输入差异、四维人工观察与单次样本边界。
- **应用迁移**：原有应用向导、三种采用层级和四条风险边界保留，并与模板目录和实验结论形成连续路径。
- **可访问与响应式**：桌面、平板、手机无页面级横向溢出；场景和模板支持方向键；搜索空状态、加载更多和复制均有可见反馈。

## 数据更新方式

目录文件 `site/catalog-data.js` 是生成物，不应手工修改。上游快照更新后，在项目根目录运行：

```powershell
node awesome-gpt-image-2-study/scripts/build-site-catalog.mjs
```

脚本会读取被父仓库忽略的 `upstream/awesome-gpt-image-2/data/cases.json` 与 `style-library.json`，重新生成站点所需的全部模板和案例数据。若切换上游提交，还要同步脚本和页面中的快照编号。

## 后续合理扩展

下一步若继续，应优先加入“保存自己的 Prompt 配方”和“同一输入的多次生成稳定性记录”，而不是继续增加静态卡片。前者验证复用价值，后者能更诚实地衡量模板是否减少结果漂移。

## 第 3 版补充交接

本轮已经完成上一节中的“保存自己的 Prompt 配方”，并把产品主入口调整为两个：真实案例图鉴与 Skill 沉淀工作台。

- 案例数据现在额外包含 `image`、`imageAlt`、`localImageUrl` 和 `remoteImageUrl`。本地研究优先读取被忽略的上游快照；Pages 部署缺少该目录时自动回退到固定提交的 GitHub Raw 地址。
- 图片组件监听加载和失败状态。首次地址失败会尝试远程地址；两次都失败时保留文字、Prompt 和来源，不显示浏览器破图标。
- Skill 工作台根据四场景生成 YAML 风格配方，包含自动路由、必填字段、补问、六段 Prompt 协议、生成前检查、生成后验收和失败策略。
- 配方书架只使用浏览器 `localStorage`，键名为 `awesome-gpt-image-2-skill-recipes-v1`，最多保存 12 条；没有后端同步或账户语义。
- 第三方案例图仍只作研究参考。不要把远程图当作项目自有资产，也不要取消页面中的授权提示和原始来源链接。

若下一轮继续，优先做“用户自定义场景 Schema”或“配方导入/导出”，让沉淀能力从四个预设场景扩展到团队自己的业务类型；实时生图和大规模案例检索仍不是当前主路径。
